# 3K Studio — production design system

Статус: визуальный и интерфейсный контракт.  
Продуктовый контекст: [master-spec.md](./master-spec.md). Ассеты: [content-assets.md](./content-assets.md).

## 1. Арт-направление

Направление — **редакционная рабочая поверхность студии**: крупная характерная типографика, тёплая печатная основа, острые конструкции и реальные интерфейсы как главный материал. Сайт должен выглядеть собранным руками проектировщиков, но оставаться понятным владельцу бизнеса.

Сохраняем текущую основу и усиливаем её точечно; радикального ребрендинга нет.

### Design contract

| Ось | Решение | Причина |
|---|---|---|
| Display / text / mono | Unbounded / Golos Text / JetBrains Mono | Узнаваемая кириллическая дисплейность + спокойное чтение + функциональные данные |
| Color core | бумага `#F4F2EC`, уголь `#17150F`, золото `#E5A43B` | Тёплая, прямая и не SaaS-палитра |
| Off-colors | синий `#2743E0`, охра `#C24A12` | Контрастные редакционные поля и различение работ |
| Radius | 0 для поверхностей и кнопок; круг только для семантически круглого | Жёсткая архитектурная система без default-card look |
| Spacing | база 4 px, основной ритм 8 px | Даёт плотную интерфейсную и крупную редакционную шкалы |
| Lines | 1 px служебная, 2 px структурная | Граница читается как часть композиции |
| Shadow | без мягких чёрных теней; один brutal-offset для интерактивного акцента | Не имитируем стандартные приподнятые карточки |
| Icons | один собственный набор продуктовых пиктограмм на сетке 24 px, stroke 1.75 px | Пиктограммы несут тип продукта и не смешиваются с библиотечными наборами |
| Motion | `cubic-bezier(.16,1,.3,1)`, быстрый отклик и один спокойный reveal | Единая физика без «анимации всего» |
| Signature | реальные интерфейсы и схемы в жёстко собранных media windows | Если убрать рабочие поверхности, сайт теряет доказательство и идентичность |
| Anti-reference | шаблонный agency-bento, тёмный acid minimal, cream-serif editorial | Не подменяем характер актуальным визуальным клише |

Тест похожего брифа: палитра и Unbounded сами по себе недостаточны. Уникальность появляется из сочетания открытых цен, рабочих медиа, прямого русского текста и индустриальной композиции. Секция, которую можно без изменений поставить другой студии, не проходит gate.

## 2. Токены

Токены реализуются CSS custom properties и потребляются компонентами. Hex/one-off значения внутри компонентов запрещены, кроме цветокоррекции конкретного медиа.

### Цвет

| Token | Значение | Роль |
|---|---|---|
| `--color-paper` | `#F4F2EC` | основной светлый фон и текст на угле |
| `--color-ink` | `#17150F` | основной тёмный фон и текст на бумаге |
| `--color-ink-soft` | `#26231A` | вложенная тёмная поверхность |
| `--color-gold` | `#E5A43B` | primary CTA, focus, ключевое значение |
| `--color-blue` | `#2743E0` | интерактивная/редакционная off-color поверхность |
| `--color-blue-dark` | `#1F35B8` | active/contrast variant синего |
| `--color-ochre` | `#C24A12` | вторая редакционная off-color поверхность |
| `--color-ochre-dark` | `#A83D0C` | active/contrast variant охры |
| `--color-danger` | `#B3261E` | ошибка формы, только с текстом/иконкой |
| `--color-success` | `#247A45` | успех, только с текстом/иконкой |

Добавить семантические aliases: `--bg-page`, `--bg-section`, `--text-primary`, `--text-muted`, `--border-subtle`, `--action-primary`, `--focus-ring`. Полупрозрачные цвета выводить через `color-mix()` из ролей, а не хранить разрозненными `rgb(...)`.

### Типографика

| Role | Desktop | Mobile | Font | Ограничение |
|---|---:|---:|---|---|
| Display XL | clamp 56–76 / .98 | 38–48 / 1.02 | Unbounded 700–800 | hero, до 3 строк desktop / 4 mobile |
| Display L | clamp 44–60 / 1.02 | 32–40 / 1.06 | Unbounded 700 | section heading, до 3 строк |
| Display M | 28–36 / 1.1 | 24–30 / 1.12 | Unbounded 500–700 | card/product title |
| Body L | 20 / 1.5 | 18 / 1.5 | Golos Text 400–500 | lead, measure ≤ 52ch |
| Body | 16 / 1.55 | 16 / 1.55 | Golos Text 400 | measure 60–72ch |
| Small | 14 / 1.45 | 14 / 1.45 | Golos Text 400–500 | подпись, не мельче 14 px |
| Label mono | 11–13 / 1.3 | 11–12 / 1.3 | JetBrains Mono 500 | uppercase, tracking .06–.08em |
| Metric | 48–76 / .95 | 40–56 / .98 | Unbounded 700–800 | tabular numerals при сравнении |

- Display-переносы на ключевых страницах проверяются вручную на 1440/1280/390/320.
- Предлоги и короткие союзы не остаются в конце строки; использовать неразрывные пробелы в контенте, не хаотичные `<br>`.
- Заголовки получают `text-wrap: balance`, основной текст — `pretty`; body не становится display-шрифтом ради эффекта.
- Mono используется для данных и меток, не для длинного текста.

### Пространство, сетка и материал

- Scale: `4, 8, 12, 16, 24, 32, 48, 64, 96, 128` px.
- Desktop container: max 1240 px, inline padding 48 px. Laptop: 32 px. Tablet: 24 px. Mobile: 20 px; на 320 px допустимо 16 px.
- Grid desktop: 12 колонок; tablet: 8; mobile: 4. Компонент может использовать CSS grid/subgrid, но смысловой порядок DOM остаётся мобильным.
- Section block padding: desktop 96–128 px, tablet 72–96 px, mobile 64–80 px. Более крупный разрыв должен быть мотивирован сменой акта, а не пустотой.
- `--radius-control` и `--radius-surface`: 0. `999px` разрешён только для статуса/круга/аватара, где форма семантична.
- `--shadow-brutal`: `10px 10px 0 var(--color-gold)` только для одного приоритетного hover/focus-приёма; не применять ко всем карточкам.
- Текстура зерна ≤ 5% opacity, `pointer-events:none`, не ухудшает контраст и отключается для печати.

### Breakpoints

| Режим | Диапазон | Правило |
|---|---|---|
| Mobile compact | 320–389 | 1 колонка, 16 px поля, сокращённые декоративные элементы |
| Mobile | 390–767 | 1 колонка, 20 px поля, медиа после объясняющего текста |
| Tablet | 768–1023 | 8 колонок, без desktop-only sticky если он мешает чтению |
| Laptop | 1024–1279 | 12 колонок, 32 px поля |
| Desktop | ≥1280 | 12 колонок, container 1240 px |

Container queries предпочтительны для переиспользуемых карточек. Breakpoint не должен скрывать содержание или действие.

### Motion

| Token | Значение | Применение |
|---|---:|---|
| `--motion-fast` | 120 ms | hover, pressed, focus feedback |
| `--motion-medium` | 260 ms | menu, accordion, local state |
| `--motion-slow` | 700–900 ms | один вход секции/маска |
| `--ease-site` | cubic-bezier(.16,1,.3,1) | основной easing |

- Reveal используется на уровне смыслового блока, а не каждого абзаца.
- Hero-wall допускает две медленные встречные дорожки; контент не зависит от их позиции. Ticker — только один перед финальным CTA/footer.
- Magnetic/cursor эффекты включаются только на fine pointer, не меняют layout и не заменяют focus-state.
- `prefers-reduced-motion: reduce`: циклы, параллакс, magnetic, cursor-follow и transform-reveal отключены; меню/accordion меняют состояние без пространственного движения.
- Не добавлять animation library, пока эффект достижим CSS и не требует сложной координации состояния.

## 3. Медиа-система: рабочая поверхность

Это главный signature, не универсальная карточка.

### Media window

- Внутри — только реальный экран, диаграмма или явно помеченный концепт.
- Browser chrome показывается, если помогает считать объект сайтом; для mobile/TMA используется device frame без фотореалистичного мокапа.
- Frame имеет структурную линию 1–2 px и нулевой radius. Декоративные traffic-light dots необязательны и не повторяются на каждой рамке.
- `object-fit: cover` запрещён для full-page UI, если обрезает важный интерфейс. Использовать contain, art-directed crop или отдельное detail-изображение.
- Подпись отвечает на вопрос «что здесь доказано», а не повторяет имя файла.
- Hero media имеет `<picture>` с desktop/mobile source, явные width/height и корректный fetch priority.

### Композиции

- **Hero workbench:** один доминирующий экран + 2–3 частичных слоя; уровни и перекрытия фиксируются композицией, а не случайным masonry.
- **Case sequence:** крупный контекстный экран чередуется с парой деталей; не более двух одинаковых grid-рядов подряд.
- **Flow strip:** 3–5 равноправных состояний сценария со стрелками/подписями; на mobile становится вертикальной последовательностью.
- **System diagram:** реальные сущности и направления данных; число узлов минимально необходимое.
- **Before/after:** одинаковый viewport/масштаб; оба состояния подписаны и доступны без drag-only interaction.

## 4. Компонентный контракт

Общее для интерактивных компонентов: hit area ≥ 44×44 px, видимый focus, семантический элемент, accessible name, disabled не только через opacity, контент не исчезает без альтернативы на mobile.

### Navigation / mobile menu

- Высота desktop 72–88 px, mobile 64–72 px; логотип ведёт на `/`.
- Primary CTA визуально один. Active route — цвет/линия + `aria-current`.
- Mobile menu — modal navigation с `aria-expanded`, закрытием по Esc/overlay, focus trap и возвратом фокуса. При no-JS основные ссылки должны оставаться доступными либо header имеет простую fallback-навигацию.

### CTA и text link

- `primary`: золото/уголь, высота не менее 52 px, padding 16×24/28.
- `secondary`: структурный outline, тот же размер и focus-area.
- `text`: подчёркивание/стрелка, не только смена цвета.
- Текст — глагол + результат: `Собрать проект`, `Смотреть работу`. Не использовать `Узнать больше`.
- В loading CTA сохраняет ширину, показывает статус и блокирует дубль.

### Product row/card

- Содержит название, одно предложение, цену, срок и статус/действие.
- Published ведёт на detail. Planned ведёт в бриф и обозначается `По запросу`/`Планируем`, не маскируется под готовую страницу.
- Desktop допускает row-композицию; mobile — цельный вертикальный блок без микроскопической правой колонки.
- Вся кликабельная область имеет одну ссылку; вложенные интерактивные элементы запрещены.

### Case preview и case media

- Preview: реальная обложка, имя, формат, одна конкретная особенность. Статус planned визуально и семантически отличается.
- Media: `<figure>` + осмысленный `figcaption`; декоративный кадр скрыт от screen reader, сам `<img>` имеет предметный alt.
- Hover-cursor label — дополнительный feedback только для мыши; ссылка понятна без него.

### Browser/device frame

- Варианты `browser`, `mobile`, `telegram`, `plain`.
- Frame не должен добавлять ложный бренд устройства. Mobile frame на узком экране становится plain media, если рамка съедает полезную площадь.
- При zoom 200% содержимое остаётся доступным; full-page screenshot может открываться по ссылке в полном размере.

### Price/specification table

- Строка содержит название, цену, срок и пояснение применимости.
- Числа выравниваются таблично; mobile превращается в labelled stack, не в горизонтально прокручиваемую таблицу без причины.
- Цена `от` и диапазон не смешиваются с фиксированной. Сноска объясняет, что меняет оценку.

### Metric

- Публикует источник/дату или контекст измерения. Live-метрика имеет loading, stale и unavailable состояния.
- Изменение числа объявляется screen reader только если оно вызвано действием пользователя; ambient updates не спамят live region.
- Неподтверждённая vanity metric запрещена.

### Quote/result block

- Quote требует имени/роли и разрешения на публикацию. Без них использовать `Результат`, а не псевдоцитату.
- Result содержит факт, единицу и контекст. Огромное число оправдано только доказательной ценностью.

### Integration diagram

- DOM/текст содержит все узлы и связи; SVG/линии декоративны или имеют доступное описание.
- Mobile — вертикальный flow. Стрелки не являются единственным носителем направления: подписи `передаёт`, `обновляет`, `уведомляет` обязательны.

### Form controls / brief step

- Visible label всегда присутствует; placeholder — пример, не label.
- Высота однострочного поля ≥ 48 px; error рядом с полем и связан через `aria-describedby`.
- Choice/radio/checkbox кликается всей строкой, имеет selected/focus/disabled состояния.
- Шаг: заголовок, короткое пояснение, ответы, back/continue и текстовый прогресс. На mobile CTA не перекрывает клавиатуру и контент.
- Summary до submit перечисляет выбранное; success получает фокус программно.

### FAQ

- Native `details/summary` или доступный accordion. Вопрос остаётся настоящим текстом; иконка декоративна.
- Допустимо открыть несколько пунктов. При reduced-motion раскрытие мгновенное.

### Article content

- Measure 60–72ch, заголовки имеют якоря, ссылки различимы, код скроллится внутри блока.
- Изображения получают подписи/источник; таблица имеет header cells и mobile-стратегию.
- Материал заканчивается релевантным CTA, а не общей рекламной плашкой.

### Footer

- Финальная точка маршрута: wordmark, продукты/работы/Lab/прайс, Telegram, legal, реквизиты/копирайт.
- Ticker расположен перед footer и скрывается/останавливается при reduced-motion.
- На mobile ссылки сгруппированы по смыслу и имеют достаточные интервалы.

## 5. Page composition rules

- На одной странице один главный визуальный момент. Остальные секции поддерживают его контрастом плотности.
- Не более двух одинаковых светлых/тёмных секций и двух одинаковых карточных раскладок подряд.
- Полноширинное медиа чередуется с constrained text; избегать одинакового `max-width` у всех блоков.
- Карты — только для повторяемых объектов. Не помещать целую секцию в карточку и не вкладывать карточки друг в друга.
- Mobile DOM-order: заголовок → объяснение → доказательство → действие. Desktop-асимметрия достигается CSS grid, не перестановкой доступного порядка.
- Sticky применяется только при наличии параллельного длинного контента и отключается там, где создаёт пустоты/перекрытия.

## 6. Visual gate и приёмка

Каждая секция проходит четыре вопроса:

1. Без логотипа она всё ещё узнаваема по типографике, палитре, прямому тексту и рабочему медиа?
2. Есть конкретное доказательство или необходимое действие?
3. Удаление эффекта разрушает смысл/идентичность? Если нет — эффект удалить.
4. На 320 px и при reduced-motion остаётся тот же смысл и следующий шаг?

Финальный аудит удаляет: generic bento, pills без семантики, градиентные blobs, card-in-card, одинаковый reveal в каждой секции, фальшивые dashboard-данные, stock/AI atmosphere, декоративные integration nodes и эффекты из UI-kit без полной адаптации.

Компонент готов, когда документированы и проверены: default, hover, active, focus-visible, disabled, loading/error/empty где применимо, mobile 320/390, keyboard, 200% zoom и reduced-motion.
