# Olginka Residence — премиальный лендинг продажи дома у моря

**Тип:** одностраничный сайт-продажник частного объекта недвижимости (дом-мини-гостиница 1 082 м² на берегу Чёрного моря, Ольгинка).
**Роль:** дизайн, фронтенд, инфраструктура и деплой — под ключ.
**Прод:** [olginka-residence.online](https://olginka-residence.online)

---

## Задача

Собственник продаёт объект напрямую, без агентств. Нужен сайт, который:

- вызывает доверие и ощущение «премиум» — объект дорогой, покупатель придирчив;
- одинаково убедительно говорит с **двумя разными аудиториями** — семьёй, которая ищет дом для жизни, и инвестором, который считает доходность;
- быстро грузится, хорошо индексируется и приводит заявки в мессенджеры и на почту;
- разворачивается на собственном VPS без привязки к платным PaaS, с воспроизводимым и безопасным деплоем.

---

## Результат кратко

- Единый арт-дирекшн, отличающий сайт от «сгенерированных» шаблонных лендингов.
- Переключатель аудитории **«Владелец / Инвестор»** — весь текстовый слой меняется под сценарий.
- First Load JS главной ≈ **126 кБ**, шрифты и изображения self-hosted и оптимизированы.
- Полный SEO-слой: метаданные, Open Graph, динамическая OG-картинка, `schema.org/RealEstateListing`, sitemap, robots.
- Zero-downtime деплой на bare-metal VPS через GitHub Actions → systemd, с healthcheck и авто-откатом.

## Стек

**Frontend**
- **Next.js 15** (App Router, React Server Components) + **React 19**
- **TypeScript** (строгий режим)
- **Tailwind CSS 3** с кастомными дизайн-токенами (палитра, типографическая шкала, easing)
- Собственные UI-компоненты, без тяжёлых UI-китов

**Инфраструктура / деплой**
- **VPS (Ubuntu)** без PaaS
- **Next.js standalone build** → tar-артефакт
- **systemd** как супервизор процесса (с hardening)
- **nginx** как reverse-proxy
- **Let's Encrypt / certbot** — TLS
- **GitHub Actions** — CI/CD (сборка → доставка по SSH → релиз)
- **nodemailer + SMTP** — обработка заявок

**Тулинг**
- ESLint (`eslint-config-next`), PostCSS/Autoprefixer
- `fonttools` — самостоятельный сабсеттинг веб-шрифтов
- `gh` CLI, воспроизводимые bash-скрипты деплоя

## Ключевые решения и практики

### 1. Двухрежимный контент под две аудитории
Один макет — два нарратива. Тумблер **«Будущий владелец / Инвестор»** через React Context переключает весь копирайт: заголовки, подзаголовки, буллеты, эмоциональные врезки, экономическое обоснование цены и даже график сезонности (для инвестора добавляется вторая серия «зимние локации»). Контент вынесен в типизированную структуру `content.life` / `content.biz` — редактируется без правки разметки. Режим ещё и подхватывается из query-параметра (`?mode=biz`) — удобно для таргетированных рекламных ссылок.

### 2. Арт-дирекшн: уход от «нейрослопа»
Осознанная работа против визуальных штампов сгенерированных лендингов:
- отказ от переезженной пары Playfair Display + моноширинные «редакционные» кикеры (`01 / ОБЪЕКТ`, псевдокоординаты);
- переход на **единый гротеск Onest** — по духу Suisse/Untitled Sans, «архитектурный премиум», с плотным трекингом крупной типографики;
- «голосовые» цитаты собственника — без синтетического курсива, с тонкой акцентной линией;
- чистые заголовки секций вместо нумерованных «журнальных» индексов.

Дизайн-решения зафиксированы в дизайн-токенах Tailwind (семантические цвета `paper/ink/terracotta/…`, шкала `hero/section/body` с готовыми `line-height` и `letter-spacing`), поэтому система остаётся консистентной.

### 3. Производительность и офлайн-устойчивая типографика
- Шрифты **self-hosted в woff2**, а не через `next/font/google` — CI-раннер бывает сетевонестабильным, а внешняя загрузка шрифтов ломала сборку. Шрифты лежат в репозитории и подключаются локально.
- **Самостоятельный сабсеттинг** вариативного Onest через `fonttools`: инстансирование под нужные веса (400/500/600/700) и деление на `cyrillic` / `latin` c точными `unicode-range`. В кириллический диапазон **специально добавлен символ рубля ₽** (U+20BD) и типографские тире — стандартный Google-сабсет их не содержит, из-за чего цена «94,9 млн ₽» отваливалась бы на нестандартный шрифт.
- Изображения — **WebP**, с корректными `sizes`/`fill` и приоритетной загрузкой hero.
- Продакшн — **standalone-сборка** Next.js: минимальный self-contained сервер, First Load JS главной ≈ 126 кБ.

### 4. SEO и разметка для поисковиков
- Полные `metadata` (title/description/keywords), canonical, Open Graph и Twitter-cards.
- **Динамическая OG-картинка** (`opengraph-image`) — генерируется рантаймом, не статичный файл.
- **JSON-LD `schema.org/RealEstateListing`**: цена, валюта, площадь, число комнат, гео-координаты, адрес, доступность — объект получает rich-представление в выдаче.
- Программные `sitemap.xml` и `robots.txt`, `lang="ru"`, семантическая структура, `theme-color`, web-manifest, apple-icon.

### 5. Заявки и интеграции
- API-роут `POST /api/contact` (Node runtime): серверная валидация имени и **российского телефона**, экранирование пользовательского ввода, отправка письма через **nodemailer/SMTP**, аккуратная обработка ошибок и понятные коды ответов.
- Прямые каналы: плавающая кнопка **WhatsApp**, Telegram, преднастроенный текст сообщения — путь до диалога в один клик.
- Проверка окружения: недостающие SMTP-переменные дают внятную ошибку, а не «тихий» сбой.

### 6. Аналитика
Подключение **Яндекс.Метрики** (clickmap, trackLinks, webvisor) через `next/script` со стратегией `afterInteractive` и защитой от повторной инициализации; счётчик управляется env-переменной и полностью отключается, если ID не задан.

### 7. Инфраструктура и деплой без PaaS
Полноценный production-pipeline на «голом» VPS:

- **GitHub Actions**: `npm ci` → `next build` (standalone) → упаковка релиза в tar → доставка по SSH (`scp`) → запуск релиз-скрипта на сервере → **smoke-check** живого `/api/health` и главной.
- **Zero-downtime релизы**: атомарное переключение симлинка `current → releases/<id>`, рестарт сервиса, **healthcheck**, и при неуспехе — **автоматический откат** на предыдущий релиз. Хранение последних 5 релизов с авто-очисткой.
- **systemd-юнит с hardening**: отдельный системный пользователь, `NoNewPrivileges`, `PrivateTmp`, `ProtectHome`, `ProtectKernelTunables/Modules/ControlGroups`, `RestrictSUIDSGID`, `Restart=always`.
- **nginx** reverse-proxy c проксированием WebSocket-заголовков и корректными `X-Forwarded-*`; **TLS** через certbot (ACME-challenge вынесен в отдельную локацию).
- **Управление секретами**: билд-тайм и рантайм-переменные разделены; рантайм-конфиг живёт в `shared/.env` вне релизов и переживает деплои; принцип наименьших привилегий — CI имеет доступ только к одному sudo-разрешённому релиз-скрипту.
- Отдельный **healthcheck-эндпоинт** `/api/health` для сервиса, CI и мониторинга.
- Всё сопровождается воспроизводимыми bash-скриптами: bootstrap VPS, деплой релиза, включение HTTPS, синхронизация секретов, ручной rollback.

### 8. Инженерная гигиена
- Строгий TypeScript, типизированный контент-слой, единый источник правды для фактов объекта (цена, площадь, координаты) — данные не дублируются между разметкой, SEO-схемой и текстами.
- Компонентная архитектура с чётким разделением `sections / ui / layout`.
- Дизайн-система в конфиге, а не «магические числа» по файлам.
- Внимание к деталям локали: неразрывные пробелы в числах и единицах, ₽, типографские тире.

## Что этот проект показывает заказчику

- **End-to-end**: от арт-дирекшна и копирайта до systemd, nginx и TLS — без перекладывания «инфраструктуры» на кого-то ещё.
- **Продуктовое мышление**: не «просто красиво», а решения под конверсию (двойной нарратив, прямые каналы связи, доверие через документы и SEO-rich-разметку).
- **Инженерная зрелость**: воспроизводимый zero-downtime деплой с откатом на собственном железе, безопасный systemd, разделение секретов — то, что обычно отличает боевой проект от «залил на хостинг».
- **Внимание к деталям**: от символа рубля в сабсете шрифта до защиты формы от инъекций.
