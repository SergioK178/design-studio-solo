# Loft Rent — сайт аренды автомобилей с онлайн-бронированием и CRM

## Задача

Заказчику нужен был лендинг для сервиса аренды автомобилей (Москва и область) с:

- реальным онлайн-бронированием (проверка доступности машин по датам), а не просто формой «оставить заявку»;
- каталогом автопарка, который заказчик может обновлять сам, без доступа к коду;
- приёмом заявок сразу в CRM отдела продаж;
- юридически корректными страницами (оферта, политика конфиденциальности, реквизиты);
- стабильным продакшеном без разработчика на телефоне при каждом мелком изменении.

## Технические решения

**Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS 4.**
Next.js выбран из-за SSR/SEO из коробки (metadata routes для `robots.txt`/`sitemap.xml`, Open Graph) и standalone-сборки, которая упрощает деплой без полного `node_modules` на сервере.

**Онлайн-бронирование через встраиваемый виджет RentProg**
(`src/components/rentprog/`). Вместо самописного календаря доступности и логики бронирования сайт интегрируется с уже работающей у заказчика системой аренды (RentProg) через её web-компонент. Это значит:
- Клиент видит реальную доступность машин на нужные даты, а не «заявку в никуда».
- Все брони автоматически попадают в систему, которой заказчик уже пользуется для управления автопарком, — не нужно дублировать учёт.
- Виджет подключается токеном через env (`NEXT_PUBLIC_RENTPROG_TOKEN`); если токен не задан (например, на стейджинге), сайт аккуратно откатывается на обычную форму заявки — сборка не падает и часть функциональности не отваливается вслепую.

**Собственная лёгкая админка (`/admin`) для управления автопарком.**
Вместо полноценной CMS — простая защищённая форма редактирования карточек машин (фото, галерея, характеристики). Причина: заказчику нужно самостоятельно добавлять/убирать модели без обращения к разработчику, но полноценная CMS для 10 карточек — избыточна.
- Данные читаются из runtime-файла (`CARS_DATA_PATH`), который живёт **вне** git-дерева и не пересобирается при каждом деплое — админ правит контент, а не код.
- При отсутствии runtime-файла используется репозиторный seed (`src/data/cars.seed.json`) — новое окружение поднимается с рабочими данными из коробки.
- Доступ защищён логином/паролем и подписанной сессией (`src/lib/auth.ts`, `src/proxy.ts`); без `ADMIN_SESSION_SECRET` авторизация намеренно считается «не настроенной», а не тихо работающей на дефолтном ключе.

**Приём заявок через amoCRM API** (`src/lib/amocrm/`).
Форма лида (`/api/lead`) сразу создаёт сделку в amoCRM отдела продаж — заявки не теряются в почте и не требуют ручного переноса.

**Инфраструктура и деплой.**
Изначально прод крутился на self-hosted GitHub Actions runner, который стоял на той же VPS, что и сама продакшен-нагрузка — сборка, рантайм и раннер конкурировали за один и тот же сервер, а сама схема была хрупкой (PM2, Nginx + Certbot, полный `node_modules` в релизе). Схему пересобрали на:

- **GitHub-hosted runner** — сборка ушла с прод-сервера полностью, VPS теперь только запускает готовый релиз;
- **standalone-релиз** Next.js вместо деплоя `node_modules` целиком — меньше, быстрее, предсказуемее;
- **`ssh + rsync`** для доставки релиза и **release-директории + symlink `current`** — мгновенный откат на предыдущий релиз одной командой, без пересборки;
- **systemd** вместо PM2 — управление процессом штатными средствами ОС, стандартные логи через `journalctl`;
- **Caddy** вместо Nginx + Certbot — автоматический HTTPS без ручного управления сертификатами.

Секреты и env разнесены на два контура: секреты сборки/деплоя (SSH-ключи, хосты) и секреты приложения (amoCRM, admin-доступ) — обновление одних не требует пересборки и наоборот (`deploy.yml` vs `deploy-config.yml`).

**Контент и правовая часть.**
Отдельная работа над юридическими страницами (оферта, политика конфиденциальности, реквизиты) с корректным рендерингом таблиц и email-ссылок в документах — важно для сервиса, который работает с персональными данными арендаторов и платежами.

## Что получилось

- Рабочий лендинг с реальным онлайн-бронированием, синхронизированным с системой учёта аренды заказчика (RentProg), а не имитацией формы.
- Заявки автоматически попадают в amoCRM — отдел продаж работает с ними в привычном инструменте без ручного переноса.
- Заказчик самостоятельно обновляет автопарк через `/admin`, не трогая код и не дожидаясь разработчика.
- Продакшен-инфраструктура с однокомандным rollback, изолированной сборкой в CI и автоматическим HTTPS — обслуживание сайта не требует постоянного присутствия разработчика.
- SEO-контур из коробки: metadata, `robots.txt`/`sitemap.xml`, Open Graph.
- Юридически оформленный сайт: оферта, политика конфиденциальности, реквизиты компании.
