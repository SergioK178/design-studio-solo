# Саммари задачи: переработка кейса «Loft Rent»

Продолжение на другой машине, где по пути `E:\Projects\Landings\loft_taxi_project`
(в WSL/подсистеме — обычный маунт диска) лежит **исходный репозиторий** самого
Loft Rent (Next.js 16.2.1, React 19, TypeScript, Tailwind CSS 4, `npm`,
проект `loft-rent@0.1.0`). На этой машине доступ к исходникам будет локальным —
без сети/Tailscale, просто через файловую систему.

## Проблема

Страница кейса «Loft Rent» в дизайн-студии (`site/src/content/cases/car-rental.md`
+ `site/src/components/ShowroomCase.astro`) сейчас:

- верхний hero-приём выглядит дёшево (жёлтый стикер-бейдж «бронь по датам» поверх фото);
- скриншоты забраны в одинаковую рамку browser-chrome почти везде подряд —
  выглядит монотонно и «техническим wireframe»;
- страница не использует кодовые элементы из дизайн-системы студии
  (палитра, карточки, аллюзии на реальный UI) — только текст + скриншот-плейсхолдеры;
- сам кейс-нарратив не читается как история.

## Прецедент решения — кейс ИМЭКС

`site/src/components/mock/MockCatalogGrid.astro` (+ `MockFrame`, `MockBar`) —
UI каталога ИМЭКС **воссоздан кодом** на токенах дизайн-системы студии
(`--m-accent`, `--m-line`, `--m-display` и т.п.), а не вставлен скриншотом.
Подробный ТЗ по этому кейсу — `tz-imeks-case-redesign.md` в корне репо, как референс
по стилю и структуре ТЗ (в этот раз делаем компактнее, без такой детализации).

## Что уже разобрано в этом репо

- `site/src/components/AssetSlot.astro` — общий компонент для скриншот-слотов.
  `frame="browser"` рисует 3-точечный browser-chrome через `radial-gradient`
  (строки ~91–101) — источник «рамки на каждом окне». Варианты: `browser | mobile | telegram | plain`.
- `site/src/components/ShowroomCase.astro` (889 строк) — рендерит текущую страницу
  Loft Rent (`presentation.variant: "showroom"`). Секции: `.sr-hero` (со `sr-sticker`
  жёлтым бейджем), `.sr-ticket`, `.sr-context`, `.sr-statement`, `.sr-covers`
  (2×`AssetSlot`), `.sr-road` (5-шаговый флоу), `.sr-screens` (2×`AssetSlot frame="browser"`),
  `.sr-mobiles` (2×`AssetSlot frame="mobile"`), `.sr-tech`, `.sr-outcome`, `.sr-cta`.
  Итого 6 инстансов `AssetSlot` со скриншотами/плейсхолдерами — основной источник
  монотонности.
- `site/src/content/cases/car-rental.md` — контентные данные кейса (facts, ticket,
  flow, statement, tech-карточки, stack, CTA). Уже написан достаточно подробно,
  трогать по минимуму (разве что уточнить под реальный UI).
- `site/src/components/CatalogCase.astro` — альтернативный презентационный вариант
  (используется для ИМЭКС), можно смотреть как референс структуры, но не обязательно
  переключать Loft Rent на него — showroom-вариант остаётся, просто переделывается.

## План переработки

1. **Открыть/изучить исходники Loft Rent** на месте (`E:\Projects\Landings\loft_taxi_project`):
   реальную палитру, компоненты каталога/карточек авто, форму бронирования
   (виджет системы учёта аренды), навигацию/header, шрифты — чтобы не выдумывать,
   а переносить настоящие паттерны.
2. **Собрать `MockLoftSite.astro`** (по аналогии с `MockCatalogGrid.astro` +
   `MockFrame`/`MockBar`) — воссоздать ключевой экран(ы) реального сайта
   (каталог автомобилей с фильтрами и/или карточку бронирования по датам)
   кодом на токенах дизайн-системы студии. Это заменит часть скриншотов
   и станет визуальной кульминацией страницы, как задумано у ИМЭКС.
3. **Сократить скриншоты**: оставить максимум 1 реальный скриншот (`frame="plain"`
   или без рамки), остальные 5 инстансов `AssetSlot` в `ShowroomCase.astro` — либо
   убрать, либо заменить на mock-компонент(ы).
4. **Переработать hero**: убрать/заменить `sr-sticker` жёлтый бейдж на что-то менее
   «дешёвое»; фото машины — дуотон в палитре сайта вместо сырого выреза, либо тоже
   заменить на код-визуал.
5. **Проверить нарратив**: пройтись по тексту `car-rental.md` — статемент, flow,
   tech-карточки — убедиться, что история («не форма, а рабочий сценарий бронирования
   с реальной проверкой доступности») читается последовательно вместе с новой
   визуальной подачей.
6. Свериться со стилем/чек-листом `tz-imeks-case-redesign.md` (сетка, типографика,
   цвета, приоритеты P0/P1/P2, критерии приёмки) — взять применимое, не копировать
   бездумно (Loft Rent — другой характер: автомобили/бронирование, а не медицинский каталог).

## Статус

Ничего из плана ещё не реализовано (0 правок в `ShowroomCase.astro`/`car-rental.md`
на момент записи этого саммари). Попытка получить доступ к исходникам Loft Rent
через LAN/Tailscale с текущей машины — заброшена в пользу прямого доступа
к репозиторию на машине, где он физически лежит на диске.
